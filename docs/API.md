# API

Контракт: [openapi.yaml](openapi.yaml). Префикс `/api/v1`. Все запросы и ответы JSON, кроме загрузки CSV через multipart и пустого ответа выхода 204. Даты RFC 3339 с часовым поясом. Значения отсутствующих показателей представлены `null`, а не нулем.

## Авторизация

`POST /auth/register` принимает `email`, `password` (12–128 символов), `displayName`. Возвращает 201 с `user` и `tokens`. Регистрация не делает пользователя оператором. В тестовом режиме выдаются права только на компании с признаком синтетических данных.

`POST /auth/login` принимает `email`, `password`. Ошибка email и пароля одинакова: 401 `INVALID_CREDENTIALS`. После десяти неудач с одного адреса вход блокируется на 15 минут. Нормализация email: trim и lowercase. Пароль не нормализуется, хранится как Argon2-хеш.

`tokens.accessToken` передается как `Authorization: Bearer <token>`. JWT живет 900 секунд; подпись, issuer, audience, срок и серверная сессия проверяются при запросе. `POST /auth/refresh` принимает `refreshToken` и возвращает новую пару. Refresh хранится в базе только как SHA-256-хеш, используется один раз; повторное использование отзывает всю сессию. Абсолютный срок сессии 30 дней не продлевается.

`POST /auth/logout` требует access-токен и возвращает пустой 204. Отзывает все токены текущей сессии. Остальные устройства остаются авторизованы.

Фронт хранит токены в `sessionStorage` текущей вкладки, выполняет одно refresh-обновление на группу параллельных запросов и удаляет токены при выходе. Это осознанный компромисс автономного прототипа. Для интеграции с банковским контуром нужен отдельный BFF/identity provider и HttpOnly-сессия; текущая регистрация не доказывает полномочия в реальной компании.

## Основной сценарий

1. `/auth/register` или `/auth/login`.
2. `GET /me`, `GET /companies`, `GET /companies/{companyId}/context`.
3. `PUT /companies/{companyId}/preferences`: роль пользователя, темы, регионы, scope.
4. `POST /companies/{companyId}/digests` с `Idempotency-Key` и периодом. Ответ 202, заголовок `Location` и запись задачи.
5. `GET /jobs/{jobId}` до `succeeded` или `failed`. При успехе `result.href` ведет на неизменяемую сводку.
6. Для вопроса: `POST .../digests/{digestId}/questions`, затем тот же цикл задачи. `parentAnswerId` продолжает диалог. Переданная клиентом история не используется как источник фактов.
7. `POST .../digests/{digestId}/feedback` сохраняет оценку; `GET /runs/{runId}/trace` возвращает журнал существенных этапов.

Пример создания сводки:

```json
{
  "scope": "company",
  "period": {
    "from": "2026-10-01T00:00:00+03:00",
    "to": "2026-10-22T00:00:00+03:00"
  },
  "maxItems": 10
}
```

Начало включительно, конец исключительно. Пустая сводка является успешным результатом с объяснением. Материалы без даты публикации не включаются в период. Фронт по умолчанию запрашивает последние 30 дней.

## Совместимость фронта

Фронт больше не обращается к `/bootstrap` и `/insights`. `api.js` выполняет получение пользователя/компаний/контекста, сохранение настроек, создание сводки, опрос задач, загрузку результата и уточнения. `models.js` преобразует структуру для сохраненных визуальных компонентов: `relevanceScore` умножается на 100 только для отображения; риски и возможности берутся из соответствующих массивов. Тип банковского источника явный, префиксы ID не используются.

Настройки и сводки изолированы по пользователю. Выбор роли ЛПР не дает дополнительных прав доступа. Чужая сводка, задача или компания возвращает 404. Оператору разрешены сбор источников и импорт CSV. У обычного пользователя эти операции возвращают 403.

## Списки и повторы

`limit` от 1 до 100; `nextCursor=null` означает конец. Курсор непрозрачен и связан с фильтрами. При изменении фильтров начинать с первой страницы. В прототипе курсор основан на смещении; при одновременном добавлении данных возможен сдвиг списка. Для больших потоков нужен переход на keyset-пагинацию.

Создание задач требует `Idempotency-Key` длиной до 128 символов. Ключ хранится 24 часа, область — пользователь + путь + метод. Повтор с тем же телом возвращает ту же задачу, с иным — 409. Для CSV сравнивается содержимое файлов вместе с версией набора. Идемпотентность создания не означает повторный платный вызов модели после аварийного падения worker: задание после истечения lease может исполниться снова.
