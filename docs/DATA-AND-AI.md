# Данные и модели

## Клиентские данные

ТЗ описывает три набора: компании (`SYNTHETIC_U`), связи обезличенных физических лиц с компаниями (`SYNTHETIC_F`, `SYNTHETIC_U`) и платежи (`BENEFICIARY`, `PAYER`, `PAY_AMT`, `PAY_CNT`). Имя платежного файла в PDF совпало с файлом связей, поэтому API различает файлы по полям multipart, а не по имени.

`POST /admin/dataset-imports` принимает `companies`, `personLinks`, `payments` и `datasetVersion`. UTF-8 CSV, разделитель `,` или `;`, кавычки и BOM поддерживаются. До 50 МиБ на файл и 100000 строк суммарно. Импорт проверяет уникальность компаний, заголовки, ссылки и неотрицательные платежи. Публикуется атомарно. Одинаковая версия с другим содержимым дает конфликт, старые сводки сохраняют собственный снимок контекста.

Выручка настоящего CSV трактуется как сумма в рублях; в синтетическом наборе поле явно помечено как миллиарды RUB. Проверьте единицы выручки конкретной выгрузки до импорта. Валюта платежей неизвестна, поэтому не подставляется RUB. Наличие кредитного продукта не означает известную долговую нагрузку. Город регистрации не равен всей географии бизнеса.

Связи физлиц преобразуются в ребра между компаниями. Физлица и их ID через клиентское API не раскрываются. Для группы более 100 участников сохраняется связный граф с опорной вершиной; это отмечается в отчете вместо создания квадратичного числа ребер.

Импорт добавляет/обновляет компании и связи. Он не удаляет отсутствовавшие в новой загрузке записи автоматически. Для полной замены набора нужна отдельная процедура очистки с проверкой актуальных доступов. ID из разных наборов должны быть согласованы.

## Оператор и доступ

Создайте оператора через `ADMIN_EMAIL` и `ADMIN_PASSWORD` в корневом `.env` до первого запуска. Операторские права не назначаются полями регистрации. Пользователь регистрируется самостоятельно, затем оператор выдает доступ:

```sh
docker compose exec api python -m app.manage grant-company user@example.com SYNTHETIC_U
```

При необходимости сделать существующего пользователя оператором:

```sh
docker compose exec api python -m app.manage make-admin operator@example.com
```

Эти команды требуют доступа к серверу. Для scope=group пользователь должен иметь доступ ко всем компаниям группы.

## Материалы и парсер

В `backend/data/sources.json` задаются только разрешенные оператором источники. Образец: `sources.example.json`. Поля: `id`, `kind` (`external_news` или `bank_analytics`), `name`, `url`, `format` (`rss`, `text`, `pdf`), `enabled`. Для текста/PDF укажите известную `publishedAt` с часовым поясом. После изменения конфигурации перезапустите API и worker.

Адрес должен использовать HTTPS. Внутренние IP не допускаются, редиректы не выполняются, ответ ограничен 8 МиБ. RSS разбирается безопасным XML-парсером; PDF — текстовым извлечением, до 100 страниц. Сканированные PDF без текстового слоя требуют предварительного OCR. RSS Atom и произвольный обход сайтов в прототипе не реализованы. Категоризация использует словарь тем, который можно расширить.

`POST /admin/material-ingestions` с `sourceIds` запускает загрузку. Автоматическое расписание по умолчанию не включено: периодический вызов этой ручки можно настроить во внешнем планировщике. Оригиналы банковских материалов из Drive нужно сделать доступными по разрешенному прямому HTTPS URL или предварительно экспортировать в текст/PDF; страница папки Drive не является самим отчетом.

Материал хранится с хешем содержимого и версией. Повтор не создает копий. Сводка содержит разрешенные выдержки и версии исходных материалов. `bank_analytics` назначает оператор только проверенному оригиналу аналитики банка. Если его нет, позиция банка не сочиняется.

## LLM

Прототип использует собственную оркестрацию, без LangChain, готовых агентов или внешних автономных AI-сервисов. Шлюз из командного комплекта `run_allowed_llm.py` уже задан: `https://changellenge.up.railway.app/v1`. Формат запросов — `/chat/completions`. Для подключения достаточно двух полей в корневом `.env`:

```dotenv
LLM_API_KEY=командный-ключ
LLM_MODEL_ID=auto
```

Можно также использовать переменную `ALFA_API_KEY` из командного комплекта; `LLM_API_KEY` имеет приоритет. Без ключа приложение продолжает работать в режиме без LLM, без внешних платных запросов.

В режиме `auto` модель выбирается из списка ниже; для ручного выбора разрешены эти ID:

| Модель | LLM_MODEL_ID |
| --- | --- |
| Gemma 4 26B A4B | `google/gemma-4-26b-a4b-it` |
| GLM-5.3-Flash | `z-ai/glm-5.3-flash` |
| Qwen3.6 35B A3B | `qwen/qwen3.6-35b-a3b` |
| DeepSeek-V4.1-Flash | `deepseek/deepseek-v4.1-flash` |
| Qwen3-VL-30B-A3B-Instruct | `qwen/qwen3-vl-30b-a3b-instruct` |
| Kimi-K2.6 | `moonshotai/kimi-k2.6` |

Адрес, семейство модели и проверка разрешённого списка определяются автоматически. После смены ключа/модели пересоздайте API и worker, чтобы Compose перечитал `.env`:

```sh
docker compose up -d --build --force-recreate api worker
```

Командный денежный лимит 500 ₽/день указан организаторами и должен обеспечиваться их шлюзом: приложение без подтверждённых тарифов не выдаёт локальный счётчик за точную сумму расходов. Дополнительно оно ограничивает обращения: по умолчанию 100 вызовов и 250000 консервативно зарезервированных токенов в сутки по московской дате, общих для всех worker этого приложения. Перед каждым запросом резервируются входной объём в байтах, запас и максимальный выход; ошибки не возвращают резерв. Настройки `LLM_DAILY_CALL_LIMIT` и `LLM_DAILY_TOKEN_LIMIT` необязательны. Расходы других приложений с тем же ключом здесь не видны.

Расширенные настройки сохранены: если заданы обе цены `LLM_INPUT_RUB_PER_MILLION` и `LLM_OUTPUT_RUB_PER_MILLION`, дополнительно действует локальный RUB-бюджет `LLM_DAILY_BUDGET_RUB` (не более 500). Для другого провайдера нужно явно указать HTTPS `LLM_BASE_URL`, конкретный `LLM_MODEL_ID`, `LLM_ALLOWED_MODEL_IDS` и обе цены; в обычном режиме эти поля не нужны. JSON mode не навязывается шлюзу: по примеру командного комплекта `response_format` отправляется только при `LLM_JSON_MODE=true`. Ответы принимаются как JSON-объекты, fenced JSON или текстовые блоки; обрезанные и некорректные ответы не исправляются автоматически.


При выключенной модели никакие данные не отправляются провайдеру. При включении в запросы попадают доступные признаки компании и выбранные материалы; пароли, токены сессий и идентификаторы физических лиц не передаются. Для реального банковского контура провайдер, политика обработки данных и сетевой доступ должны быть согласованы отдельно.

## Агентный процесс

1. Планирование направлений анализа.
2. Получение снимка контекста компании/группы и роли.
3. Поиск доступных материалов по периоду, темам и географии.
4. Классификация источников, выделение фактов, дедупликация.
5. Ранжирование по признакам и роли.
6. Интерпретация с банковскими материалами и причинными сценариями.
7. Проверка существования источников, версий, точности выдержек, признаков и связей оснований.
8. При невалидном ответе — повтор генерации с сигналом проверки, максимум один раз.

В трассировке сохраняются инструменты/этапы, статусы, ID источников и признаков. Сырые скрытые рассуждения модели не сохраняются и не выводятся. Проверка ссылок является структурной: она не доказывает логическую истинность всех выводов. Нужны экспертная разметка, проверка причинных связей и оценка на новых реальных новостях.

Промпт отделяет данные материалов от инструкций. Инструменты фиксированы кодом, пользователь и материал не могут запускать команды, менять права, отправлять банковские платежи или выбирать произвольные URL/модели. Для дополнительной защиты от DNS rebinding в production нужен сетевой egress allowlist: проверка DNS внутри приложения не заменяет сетевую изоляцию.

### Автоматический выбор модели

`LLM_MODEL_ID=auto` (по умолчанию) выбирает модель локальными правилами без отдельного платного запроса:

| Условие (в порядке приоритета) | Модель |
| --- | --- |
| Повтор после ошибки проверки структуры или ссылок ответа | GLM |
| Контекст от 24 000 байт UTF-8 или от 8 материалов | DeepSeek |
| Планирование: выбор направлений и тегов | Gemma |
| Интерпретация события и последствий | GLM |
| Вопрос со словами «почему», «сравни», «сценарий», «что если» или специальная перспектива | GLM |
| Остальные вопросы | Qwen |

Это начальная эвристика, не оценка качества или стоимости моделей. Содержимое новостей не используется для поиска ключевых слов; анализируется вопрос пользователя. ID нельзя задать текстом запроса. Для единственной модели укажите её конкретный ID вместо `auto`. Автовыбор работает со шлюзом организаторов; собственный провайдер и ручные тарифы требуют конкретного ID. Qwen VL автоматически не вызывается: текущий вход текстовый.

В трассировке записываются фактически вызванные модели и причина выбора. Общие лимиты действуют для всех моделей совместно. При сетевой ошибке или отказе шлюза скрытого переключения на другую модель нет; существующий повтор после ошибки проверки ответа также учитывается в лимитах.
