# Развертывание

## Один Compose-проект

Минимум: Linux с Docker Engine и Compose v2.24+, 2 CPU и 2 ГБ RAM для прототипа. Модель вызывается через внешний разрешенный HTTP endpoint; веса LLM на сервер не загружаются.

```sh
docker compose up -d --build
```

Backend: PostgreSQL → одноразовая миграция → API → worker. Frontend: nginx с прокси `/api/v1`. Compose сам создаёт общую сеть `alfa-pulse-edge`; nginx запускается после готовности API. БД не публикует порт на хост. API доступен только через `127.0.0.1:8000`, frontend — `127.0.0.1:8080`. Межсерверное развертывание потребует другого upstream и сетевого туннеля; текущие файлы рассчитаны на один Docker-хост.

По умолчанию сеть PostgreSQL внутренняя, worker имеет отдельную сеть для исходящих HTTPS-запросов к источникам и LLM. API подключен к общей сети frontend. Контейнеры приложения работают без root и дополнительных capabilities.

## Настройка перед публичным размещением

Скопируйте корневой `.env.example` в `.env` рядом с `compose.yaml`. Задайте свои пароли, секрет JWT, `DEMO_DATA=false` и параметры оператора. Не коммитьте `.env`. `POSTGRES_PASSWORD` после создания тома не меняет пароль уже созданной роли: для ротации нужна операция внутри PostgreSQL, а затем обновление конфигурации.

Если синтетические данные уже были загружены, `DEMO_DATA=false` предотвращает новые выдачи доступа к ним, но не удаляет ранее созданные записи. Для реальных данных используйте отдельное чистое окружение/том с заранее настроенным `DEMO_DATA=false`.

Снаружи публикуется только HTTPS reverse proxy. Пример Caddy-конфигурации: `deploy/Caddyfile.example`. Запускайте Caddy на том же сервере перед `127.0.0.1:8080`. Настройте DNS своего домена и TLS, не открывая PostgreSQL или служебный API-порт. Пример не загружает сертификаты и не меняет DNS автоматически.

Для HTTP-тестирования с другой машины можно задать `WEB_BIND=0.0.0.0`, но перед передачей настоящих паролей нужен HTTPS. Все команды ниже выполняются из корня репозитория, настройки читаются из корневого `.env`:

```sh
docker compose up -d --build
```

## Обновление и откат

`deploy/update.sh` получает текущую ветку fast-forward, собирает образы и обновляет все сервисы общего проекта. Перед обновлением сделайте резервную копию. Для отката выберите проверенный commit/tag, пересоберите образы. Миграции данных могут быть несовместимы со старым кодом, поэтому автоматический откат БД не выполняется.

```sh
sh deploy/backup.sh
sh deploy/update.sh
```

Копия создается в `backups/` с правами только владельца. Каталог исключен из Git. Проверять восстановление следует на отдельной тестовой базе. Остановка обычным `docker compose down` не удаляет том PostgreSQL; вариант `down -v` удаляет данные и для рабочего окружения не используется.

## Диагностика

```sh
docker compose ps
docker compose logs --tail 100 postgres migrate api worker web
curl --fail http://127.0.0.1:8000/healthz
```

Ошибка 502 на фронте обычно означает, что backend еще не готов или nginx не может подключиться к API. `queued` без прогресса — проверьте worker. После аварии worker задача `running` может ждать до десяти минут до повторного захвата; результат записывается под заранее выделенным ID. Вызов LLM может повториться, если процесс завершился после ответа провайдера и до сохранения результата, поэтому бюджет резервируется перед каждым вызовом.

Нужны внешние политики хранения и резервного копирования. Сейчас сессии/refresh, оценки и снимки автоматически по времени не удаляются. Для больших объемов потребуются очистка истекших данных, keyset-пагинация и специализация таблиц JSONB. Долгие PDF/CSV и ограничения ресурсов следует вынести в отдельные очереди и подобрать по нагрузочным тестам.

## Переход с раздельного запуска

Если раньше использовались два Compose-проекта, перенесите настройки из `backend/.env` в корневой `.env`, а `WEB_BIND`/`WEB_PORT` — из `frontend/.env`. Остановите прежний frontend перед общим запуском, чтобы освободить порт:

```sh
docker compose -f frontend/compose.yaml down
docker compose up -d --build
```

Имя проекта сохранено: `alfa-pulse-backend`, поэтому стандартный том `alfa-pulse-backend_postgres-data` будет использован повторно. Если старый backend запускался с собственным `-p`/`COMPOSE_PROJECT_NAME`, передайте то же имя общему запуску. Не используйте `down -v` при переходе. Пароль в `.env` должен совпадать с паролем роли в существующем томе.
